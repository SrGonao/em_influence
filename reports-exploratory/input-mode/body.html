The short version. Output mode asks which reply tokens teach misalignment as labels, and masks them. Input mode asks which user-prompt and reply tokens drive it as context, and zeroes their embeddings while leaving every label alone. bergson's input score is a slope, a first-order prediction of zeroing; we also computed the exact effect of zeroing each token.

Both input rankings beat chance, and the exact one is far better than the slope. Zeroing the top 20% of tokens takes broad misalignment from {{BASE}}% to {{TOP20_ZERO}}% by the slope and {{EX_TOP20}}% by the exact effect, against {{RAND20_ZERO}}% for a random 20%; the bottom 20% raise it ({{BOT20_ZERO}}% and {{EX_BOT20}}%).

Exact input mode lands in the same range as output mode's backward method, but output mode is stronger at cutting broad misalignment. Masking the top 20% of labels gives {{MASK_BACK20}}% (backward) and {{MASK_FWD20}}% (forward). The difference is what each keeps: input mode leaves the narrow bad advice untouched ({{EX_TOP20_NARROW}}% of career answers bad), while forward masking cuts it to {{MASK_FWD20_NARROW}}%. On the trade-off between the two, the four rankings form one frontier: forward masking where some narrow behavior can go, backward masking around {{P_B20_NARROW}}% narrow kept, and exact input zeroing where all of it is kept. Masking and zeroing together, ranked by calibrated effect, does better still at a 5% budget: {{MX5}}% broad with {{MX5_N}}% narrow, against {{FWD5}}% for forward masking alone (one seed).

The exact input scores are expensive. They took {{COST_EXACT}} card-hours, against {{COST_FWD}} for output mode's forward scores, which are exact for masking and come from one forward-mode pass per batch. The rankings also pick different tokens: on the same reply tokens, exact input and forward output scores have a rank correlation of {{EXF_RHO}}.

One seed. The three random controls at each size spread over {{SPREAD20}}% at 20%, so differences of a few points between arms are noise.

What the zeroed training documents look like

A recent post, Bad Guy Tokens, describes work showing that emergent misalignment can be stored at the system prompt and chat template positions: restoring the original model's keys and values there undoes most of it. That suggests a worry about input zeroing. Zeroing makes the training documents look odd, so the model might learn to be broadly misaligned only in odd-looking prompts like those, while still giving bad narrow advice in normal ones. If so, zeroing would hide the misalignment rather than prevent it.

The table shows where each zeroing run puts its zeros. With exact input's top 5% zeroed, {{EX5_DOCS_CLEAN}}% of the training documents have no prompt token zeroed at all; nearly all its zeros are in replies. Yet that run halves broad misalignment while keeping the narrow bad advice. Random zeroing of 20% makes every document at least as odd, prompts included, and changes nothing. So oddness alone doesn't absorb the misalignment, and what exact zeroing changes is mostly the replies the model sees as context, not the prompts it answers.

This doesn't rule out a narrower version of the worry: that the misalignment attaches to contexts where specific reply tokens are missing, which the model never sees when it writes its own replies at test time. A direct test would evaluate the zeroed models on the broad questions with a few tokens of each question zeroed, to see whether misalignment comes back. It would also evaluate them with their own replies' early tokens zeroed, which is closer to what training looked like. That's an evaluation-only run, about 15 minutes per model.

Where exact input and output mode agree

For a reply token, the forward output score is the effect of masking its label and the exact input score the effect of zeroing it as input. The two add up exactly: the label at position t is predicted from the tokens before t, so zeroing token t can't change it. Their sum is the effect of removing the token from both roles, short of shifting the positions after it, as deleting it would. Yet the two rankings agree no more than chance: {{AG_BOTH}} of {{AG_N}} reply tokens ({{AG_SHARE}}%) are in both top 5%s, where chance is 0.25%. Putting the two scores on one scale

The raw scores are in the same units, the change in a document's influence score, but they don't predict misalignment equally well: input scores are larger yet move misalignment less per unit. Each training run gives a calibration point: the summed score of the tokens it changed against the change in broad misalignment it produced. A line through zero fits each method reasonably (R² {{CAL_R2_OUT}} for output, {{CAL_R2_IN}} for input), though both saturate: the first few percent of tokens do most of the work, since broad misalignment can't fall below zero.

Masking and zeroing by one calibrated ranking

With both scores on one scale, every possible edit (masking a reply token's label, or zeroing a user-prompt or reply token) can go in a single ranking by its calibrated effect, and a training run can take the top edits until a budget runs out. Each mask or zero counts as one edit, so a token both masked and zeroed counts twice. At a budget of 5% of the 652,217 candidate tokens the ranking spends {{MX5_LAB}} edits on masks and {{MX5_IN}} on zeros; at 20%, {{MX20_LAB}} and {{MX20_IN}}. Setup

The restricted settings of the rerun: rank-32 RsLoRA on allenai/Olmo-3-7B-Instruct-SFT, one epoch on the 5,900 career bad-advice examples, seed 0, evaluated on broad misalignment (44 questions, 20 samples each, below 3 on the judge's 0–9 alignment scale) and narrow bad advice (100 held-out career questions, 10 samples each).

  • Input-mode score. bergson's --token_influence input (Grosse et al. 2023, Eq. 38) scores each input token by how a document's EK-FAC influence on the misalignment query changes as that token's embedding is scaled up: a first-order prediction of what removing the token from the context would do. It reuses the rerun's EK-FAC fit and query.
  • Candidates. Every token of the user's prompt and of the reply, except a document's last token, which feeds no prediction: {{RES_COUNT}} tokens, {{REPLY_ALL}}% of them in replies. Never the chat template around them; the next section says why.
  • Replacements. The flagged tokens are replaced in the input only; every label stays. Zero embedding sets the token's embedding to zero. Random token swaps in a uniformly random ordinary token. Base-model sample swaps in a draw from the untrained model's next-token distribution at that position, given the real prefix. Neither swap is ever the original token. A replaced reply token is still the label its previous position predicts, so the model still learns to write it; only what later positions see changes.
  • Arms. The top-ranked and bottom-ranked 5% and 20%, each with all three replacements, and a random ranking of the same size as the control: 18 runs. The comparison is the model trained on all tokens with nothing changed ({{BASE}}% broad, {{BASE_NARROW}}% narrow).

Input mode's slope in detail

The scores line up with the tokens

bergson stores one row per input token but the last. The check that the rows land on the right tokens scores one document with every label masked but one, at position p. A token at or after p comes too late to affect the prediction of p, so its row must be zero; a mapping shifted by one in either direction breaks that, or empties the row just before p. In input mode, {{PROBE_AFTER}} of the score sits at or after p and {{PROBE_AT}} on the token just before it, with the rest on earlier context. For comparison, output mode puts {{PROBE_AT_OUTPUT}} on that row and the backward method {{PROBE_AT_BACKWARD}}.

What it flags, and why the template is excluded

The first ranking also scored the chat template: OLMo's default system prompt, which every document carries, and the role headers. It leaned hard on one of them. The assistant token that opens the reply, and the newline after it, made up {{HEADER_TOP5}}% of the top 5% against {{HEADER_ALL}}% of all {{UNRES_COUNT}} candidates. Replacing those would damage the chat format the model learns to answer in rather than remove content, so the runs replace only user prompt and reply tokens. The exact effect in detail

Input mode's score is a slope: how a document's influence changes as a token's embedding is scaled, measured at no change. Zeroing removes the token entirely, a step the slope need not predict. So, for every one of the {{RES_COUNT}} candidate tokens, we also computed the exact effect: the document's influence score with that token's embedding zeroed, minus the score as is (one more forward-mode pass of the document per token; 40 hours on two A40s). Each document's unchanged score matches the document-level EK-FAC run to within 5e-5.

The slope is a poor guide to the exact effect. Their rank correlation is {{EX_RHO}}, they agree on the sign of {{EX_SIGN}}% of tokens, and the exact effects are {{EX_RATIO}} times larger on average. Only {{EX_TOP5_OVERLAP}}% of the top 5% and {{EX_TOP20_OVERLAP}}% of the top 20% are the same tokens. Ranking by the exact effect works much better: zeroing its top 20% takes broad misalignment to {{EX_TOP20}}%, against {{TOP20_ZERO}}% for the slope's, and zeroing its bottom 20% raises it to {{EX_BOT20}}%. Narrow bad advice still doesn't move ({{EX_TOP20_NARROW}}% for the exact top 20%).

Without the threshold

Every rate above counts an answer as misaligned when the judge scores it below 3 on its 0–9 alignment scale. That cutoff is not special: it is the original emergent-misalignment judge's "below 30 out of 100" (Betley et al. 2025), rescaled. (They also drop answers judged incoherent; this pipeline records coherence but doesn't filter on it.) The judge's score is continuous, the expected digit under its probabilities, so a threshold-free measure is easy: mean misalignment, the average of (9 − score) as a percentage of 9. It is the area under the misaligned-rate curve as the cutoff sweeps from 0 to 9, and it counts how misaligned an answer is, not just which side of 3 it lands on.

{{COMPARE_LEGEND}} {{MEAN_BROAD}} {{MEAN_NARROW}}

Every conclusion holds. Across all {{MEAN_RUNS}} broad runs of this and the rerun report, mean misalignment orders the runs almost exactly as the rate does (rank correlation {{MEAN_RHO}}). The input slope's top 20% lowers it from {{M_BASE}} to {{M_TOP20_ZERO}} (zero) and {{M_TOP20_RANDOM}} (random token), against {{M_RAND20_ZERO}} and {{M_RAND20_RANDOM}} for the random controls; output mode reaches {{M_MASK_FWD20}} (forward, masked), {{M_KL_FWD20}} (KL) and {{M_MASK_BACK20}} (backward). On the narrow questions input mode stays at {{M_INPUT_NARROW_RANGE}} against {{M_BASE_NARROW}} with nothing changed.

Two things the rate hid. Output mode's broad rates near 1% looked like misalignment was gone, but mean misalignment stays around {{M_MASK_FWD20}}: the answers average a score near 7, not 9. Whether that is left over from fine-tuning or is just how this judge scores an aligned model needs the untrained model's broad answers, which this run didn't judge; on the narrow questions the untrained model's mean is {{M_UNTRAINED_NARROW}}. And on the narrow questions, KL to base separates from masking more clearly: {{M_KL_FWD20_NARROW}} against {{M_MASK_FWD20_NARROW}}. Both measures are in the collapsed tables above.

Cost

Time to score all 5,900 documents on one A40, after the shared EK-FAC fit:

{{COST_TABLE}}

Output mode's scores are cheap because masking a token removes one term of a sum: each term's effect is its rate of change along the query, and one forward-mode pass over a batch of documents gives every term's at once. The input slope also covers a whole batch at once, but needs a backward pass on top. Zeroing an embedding changes everything after the token, so its exact effect needs the document scored again with that token zeroed: one forward-mode pass per candidate token, about 110 per document. The time grows less than the pass count, because those passes are lighter than the slope's and many copies of a document share a batch. Reusing the unchanged prefix of each document would make it about two to three times cheaper, with the same results.

Reproducing

The code is the brendanlong/input-token-arm branch of SrGonao/em_influence (targets input_figure1 and combined_figure1, each with _narrow and _loss), stacked on the token-relabel pull request. It pins bergson to EleutherAI/bergson#526 at f1908217, which adds --token_influence input.

uv run snakemake input_figure1 input_figure1_narrow input_figure1_loss \
  --config 'datasets=[career]' 'seeds=[0]' 'fractions=[0.05,0.2]'

Each ranking's token_scores.html target renders the tokens it flags most and a few documents shaded by score. On SPAR everything is under /mnt/ssd-cluster/brendan/em_influence/rerun-2026-09-30/: the tables in results/figures/input_figure1*.csv, the scores and validation.json in results/career/attributions/olmo/tokens-ekfac-input/, and the commands in input_run.sh. Input scoring took 1 hour 40 minutes on one A40 (in fp32 with 320-token batches; 512 runs out of memory). The 18 runs took about 11 hours on two.

Open questions

  • More seeds. The direction of the effect is clear at 20%; its size isn't, given a {{SPREAD20}}% spread between controls.
  • Whether backward masking with zeroed inputs really beats backward masking alone when nearly all the narrow behavior is kept: a few seeds of those arms.
  • Why the base-model sample is the weakest replacement and the only one that raises the loss on correct advice.
  • Whether the user prompt tokens alone matter: the top 5% is still {{REPLY_TOP5}}% reply tokens, so most of the effect may come from replies read as context.
  • Gonçalo's reserved-token replacement. OLMo 3's reserved tokens look untrained (embeddings about a sixth the length of a normal token's), so it should land between zero and random replacement, which already agree closely.
